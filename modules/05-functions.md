# M05 函数

> 本模块说明如何用函数声明和定义建立清晰接口，理解值传递、作用域与存储期，并设计递归、参数和返回值。学完后应能把问题拆成可测试的小函数，明确输入、输出、错误契约及对象生命周期。

## E05.01 函数声明、原型与定义

- **标签**：`声明与定义` `程序结构` `参数传递` `返回值`
- **难度**：入门
- **前置**：E01.03
- **关联**：E05.02、E05.05、E01.02

### 概念解释

函数声明向编译器描述名称、返回类型和参数类型，定义则还提供函数体；带完整参数类型的声明称为函数原型。调用点必须能看到兼容声明，编译器才能检查参数数量、转换实参并解释返回值。

### 语法要点

- 原型形式如 `int square(int value);`，定义形式为 `int square(int value) { ... }`，末尾不是独立声明的分号。
- 无参数函数应声明为 `int f(void)`；在 C11/C17 中，`int f()` 表示未提供参数信息，不等价于 `(void)`。
- 函数定义也是声明；在调用前给出定义可以省去单独原型，但头文件共享接口时通常使用原型。
- 非 `void` 函数应通过 `return expression;` 返回兼容值，`void` 函数可用 `return;` 提前结束。
- C99 起不再允许依赖隐式 `int` 或调用未声明函数；函数外部链接定义在一个程序中只能有一个。

### 使用场景

原型适合在头文件公开接口、处理函数相互调用和控制定义顺序。只在单个源文件使用的小函数可放在调用点之前并限制链接范围；不要为了少写声明而依赖过时编译器的隐式声明行为。

### 示例

```c
#include <stdio.h>

int square(int value);

int main(void)
{
    int result = square(7);

    if (printf("square=%d\n", result) < 0)
    {
        return 1;
    }

    return 0;
}

int square(int value)
{
    return value * value;
}
```

原型让 `main` 在定义出现之前即可正确调用 `square`；本例输入为 7，乘法在 `int` 范围内。

### 注意事项

- 原型与定义的返回类型或参数类型必须兼容，参数名称可以不同，但类型不能悄悄改变。
- 有返回值的函数若控制流到达函数末尾且调用方使用该值，会产生未定义行为；应检查所有返回路径。
- `square` 这类通用算术函数要注明可接受值域，或由接口加入溢出检查，不能对任意 `int` 假定平方可表示。

### 常见问题

**问：函数原型中的参数名可以省略吗？**

答：可以，`int square(int);` 合法；保留有意义的名称通常能提高接口可读性，并让头文件本身更接近使用说明。

## E05.02 值传递与参数求值

- **标签**：`参数传递` `返回值` `表达式` `未定义行为`
- **难度**：入门
- **前置**：E05.01、E03.03
- **关联**：E05.05、E06.03

### 概念解释

C 的函数参数全部采用值传递：形参对象由对应实参的值初始化，函数修改形参本身不会直接修改调用方变量。传入指针可以让函数间接访问调用方对象，但被复制的仍然是指针值，这不叫引用传递。

### 语法要点

- 实参会按原型转换为形参类型，类似赋值转换；原型缺失或参数类型不兼容会破坏这种检查。
- 函数内 `value = value + 1;` 只修改当前调用的形参对象，返回新值可让调用方显式接收结果。
- 若参数是 `int *p`，`p` 本身是副本，但 `*p` 可访问它指向的对象；调用方必须提供有效地址并满足生命周期要求。
- 数组作为函数实参时通常退变为指向首元素的指针，不复制整个数组，详见 E06.03。
- 各实参求值顺序未指定；同一对象的未排序多次修改会造成未定义行为，不能依赖从左到右执行。

### 使用场景

值传递适合小型标量和不需要修改调用方状态的计算。需要输出多个结果时可使用输出参数配合状态返回值；大型只读数据通常传指针或数组视图，但必须同时表达有效长度和访问权限。

### 示例

```c
#include <stdio.h>

int add_one(int value)
{
    return value + 1;
}

int main(void)
{
    int original = 41;
    int changed = add_one(original);

    if (printf("original=%d, changed=%d\n", original, changed) < 0)
    {
        return 1;
    }

    return 0;
}
```

`original` 保持 41，函数计算并返回 42；这里不存在隐式修改调用方变量的行为。

### 注意事项

- 不要用 `f(i++, i++)` 这样的实参组合；把每次修改拆成独立完整表达式后再传值。
- 形参是独立对象，对其取地址后返回该地址会导致调用结束后指针失效。
- 标量值传递仍会进行类型转换，窄化或超范围问题应按 E02.06 检查。

### 常见问题

**问：传入指针后函数能修改调用方对象，是否证明 C 支持引用传递？**

答：不能这样定义。指针值仍被复制给形参；能修改的是它所指向的对象。给形参指针重新赋值，不会改变调用方保存的那个指针变量。

## E05.03 作用域、链接与存储期

- **标签**：`作用域` `生命周期` `声明与定义` `初始化`
- **难度**：进阶
- **前置**：E01.03、E02.04、E05.01
- **关联**：E05.04、E06.05

### 概念解释

作用域决定名称在源码哪里可见，链接决定不同作用域或翻译单元中的同名声明是否指同一实体，存储期决定对象何时存在。三者相互关联但不能混为一谈：局部 `static` 对象只有块作用域，却具有静态存储期。

### 语法要点

- 文件作用域名称从声明处到翻译单元末尾可见；块作用域名称到所在块结束；函数原型作用域和函数作用域另有专门规则。
- 普通块内局部对象具有自动存储期，进入块时创建、离开块时结束；静态存储期对象在程序运行期间存在。
- 块内 `static` 使对象具有静态存储期并只初始化一次，但不扩大名称的块作用域，也不赋予外部链接。
- 文件作用域函数或对象声明中的 `static` 表示内部链接；`extern` 用于声明具有外部链接的实体，具体还受先前声明影响。
- C11 的 `_Thread_local` 指定线程存储期，可与 `static` 或 `extern` 组合；动态分配存储期由分配和释放函数管理。

### 使用场景

局部 `static` 适合确需跨调用保留的私有状态，例如单线程示例中的序列号；文件作用域 `static` 适合隐藏翻译单元内部实现。可重入、并发或可测试性要求较高时，应避免可变的隐藏静态状态，改为由调用方显式传入上下文。

### 示例

```c
#include <stdio.h>

unsigned int next_ticket(void)
{
    static unsigned int serial = 0u;

    serial += 1u;
    return serial;
}

int main(void)
{
    unsigned int first = next_ticket();
    unsigned int second = next_ticket();

    if (printf("first=%u, second=%u\n", first, second) < 0)
    {
        return 1;
    }

    return 0;
}
```

`serial` 只在 `next_ticket` 内可按名称访问，但其值跨调用保留，因此输出为 1 和 2。

### 注意事项

- 返回局部自动对象的地址会在函数返回后形成悬空指针，调用方不能继续访问该对象。
- 局部 `static` 的持久状态可能引发重入和数据竞争问题；C11 线程环境中需要额外同步。
- 内层同名声明会隐藏外层名称，但不改变外层对象的存储期；避免无意义的遮蔽。

### 常见问题

**问：`static` 是否无论写在哪里都表示“值一直保留”？**

答：不是。块内 `static` 主要改变存储期，文件作用域 `static` 主要把链接限制为当前翻译单元；必须结合声明位置判断。

## E05.04 递归、终止条件与调用成本

- **标签**：`递归` `返回值` `性能`
- **难度**：进阶
- **前置**：E05.01、E05.02
- **关联**：E05.03、E04.03

### 概念解释

递归是函数直接或间接调用自身的计算方式。正确递归需要至少一个不再递归的基本情形，并保证每次递归都朝该情形推进；否则调用不会按预期结束，并可能耗尽实现的调用资源。

### 语法要点

- 直接递归是在函数体调用自身，间接递归经过其他函数回到自身；相互递归函数需要提前原型声明。
- 基本情形必须直接返回结果，例如 `factorial(0) == 1`；一般情形把问题缩到 `n - 1`。
- 每次调用有自己的形参和自动局部对象，块内 `static` 对象却由所有调用共享。
- 标准不保证固定的最大递归深度，也不要求编译器执行尾调用优化；不能把尾递归当作自动节省空间的保证。
- 递归中的算术仍受类型范围限制，阶乘等快速增长函数必须在接口层限制输入或检查溢出。

### 使用场景

递归适合树、分治和天然递归定义的问题。简单重复计算通常迭代更直接；深度不可控的输入、严格内存限制或硬实时环境应优先评估显式栈或迭代方案。

### 示例

```c
#include <stdio.h>

unsigned long long factorial(unsigned int n)
{
    if (n == 0u)
    {
        return 1ull;
    }

    return (unsigned long long)n * factorial(n - 1u);
}

int main(void)
{
    unsigned int number = 10u;
    unsigned long long result = factorial(number);

    if (printf("%u!=%llu\n", number, result) < 0)
    {
        return 1;
    }

    return 0;
}
```

本例时间复杂度和递归调用空间需求均为 O(n)，且 10 的结果可由 `unsigned long long` 表示；该实现并未声明能处理任意大的 `n`。

### 注意事项

- 检查基本情形是否覆盖所有入口，并验证递归参数确实缩小或朝结束状态推进。
- 不要在递归深度未知时假设“栈足够大”；资源耗尽的诊断和处理方式由具体实现环境决定。
- 重复子问题可能造成指数级重复计算，必要时使用记忆化或改写成动态规划。

### 常见问题

**问：把递归调用放在函数最后一条 `return` 中就一定不会占栈吗？**

答：不一定。本例在递归返回后还要做乘法，甚至不是尾调用；即使写成 `return f(...)` 这样的尾调用，C 标准也不强制优化，实际是否节省栈空间取决于编译器、调用约定和优化设置。

## E05.05 参数、返回值与错误契约设计

- **标签**：`参数传递` `返回值` `错误处理` `边界检查`
- **难度**：进阶
- **前置**：E05.01、E05.02、E03.01
- **关联**：E04.01、E06.03、`<limits.h>`

### 概念解释

好的函数接口应明确有效输入、成功结果、失败状态和输出对象何时被修改。返回值既可承载计算结果，也可承载状态，但把两者混在同一个整数中容易产生哨兵值与合法结果冲突。

### 语法要点

- 常见模式是返回 0 表示成功、非零区分错误，并通过调用方提供的有效地址写输出；也可返回结果结构体或使用专用状态类型。
- 输出参数应说明失败时保持不变、置零还是不确定；让失败时保持不变通常更便于调用方恢复。
- 指针参数要说明是否允许空指针、指向多少元素以及是否只读；只读指针可使用 `const` 限定所指向对象。
- 返回码与调用方处理必须一致，函数内部打印错误不能替代可编程判断的状态通道。
- 对算术结果不可表示、除数为零等失败应在操作前检测，不能先触发未定义行为再报告错误。

### 使用场景

适合解析、数学计算和任何可能失败的 API。若返回值的所有取值都是合法结果，例如可正可负的商，使用 `-1` 同时表示错误会歧义；此时应分离状态和结果。

### 示例

```c
#include <limits.h>
#include <stddef.h>
#include <stdio.h>

int divide(int dividend, int divisor, int *quotient)
{
    if (quotient == NULL || divisor == 0)
    {
        return 1;
    }
    if (dividend == INT_MIN && divisor == -1)
    {
        return 2;
    }

    *quotient = dividend / divisor;
    return 0;
}

int main(void)
{
    int quotient = 0;
    int status = divide(20, 3, &quotient);

    if (status != 0)
    {
        fputs("division failed\n", stderr);
        return 1;
    }
    if (printf("quotient=%d\n", quotient) < 0)
    {
        return 1;
    }

    if (divide(20, 0, &quotient) == 0)
    {
        return 1;
    }

    return 0;
}
```

返回 1 表示参数无效，返回 2 表示商不可表示；失败路径不会写入 `quotient`。

### 注意事项

- 不要只检查除数 0 而遗漏 `INT_MIN / -1`；有符号整数不能表示该商时属于未定义行为。
- 调用方必须检查状态后再读取输出参数，失败时旧值不代表本次计算结果。
- 接口若需区分更多原因，可使用明确的状态枚举和诊断机制，避免魔法数字持续扩张。

### 常见问题

**问：函数已经向 `stderr` 打印了错误，还需要返回状态吗？**

答：需要。打印面向人，返回状态面向程序控制流；调用方可能希望重试、回退或聚合错误，不能依赖解析终端文本。
