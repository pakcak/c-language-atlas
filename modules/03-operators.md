# M03 运算符

> 本模块说明运算符如何组成表达式、何时产生副作用，以及类型转换、求值顺序和优先级如何共同决定结果。学完后应能安全使用算术、逻辑、自增和位运算，并主动识别溢出、非法移位与未排序副作用。

## E03.01 算术运算符与赋值运算符

- **标签**：`表达式` `赋值` `整数溢出` `未定义行为`
- **难度**：入门
- **前置**：E02.01、E02.06
- **关联**：E03.03、E03.05、E05.05、`<limits.h>`

### 概念解释

算术运算符由操作数计算新值，赋值运算符则把值存入左侧对象并产生表达式结果。二者都可能触发通常算术转换；有符号溢出和非法除法不是普通“错误值”，而会使整个程序失去标准行为保证。

### 语法要点

- 二元 `+`、`-`、`*`、`/` 用于算术，`%` 只用于整数；一元 `+`、`-` 分别执行提升和取负。
- 整数除法向零截断，`-7 / 2` 为 `-3`；余数满足 `-7 % 2 == -1`，其符号与被除数一致。
- 任一除法或取模的右操作数为 0 时行为未定义；商不能表示时（如二补码平台上常见的 `INT_MIN / -1`）也未定义。
- 简单赋值 `a = b` 先把右侧值转换为左侧对象类型；赋值表达式本身不是可修改的左值。
- 复合赋值 `a += b` 大致等价于 `a = a + b`，但左侧只求值一次，且包含必要的类型转换。

### 使用场景

算术运算适合计数、索引和数值计算，复合赋值适合累加或更新状态。平均值等计算若直接使用 `(a + b) / 2`，应先证明加法不溢出；处理时间、容量等外部数据时，计算前检查比计算后补救更可靠。

### 示例

```c
#include <limits.h>
#include <stdio.h>

int main(void)
{
    int dividend = 17;
    int divisor = 5;
    int total = 10;

    if (divisor == 0 || (dividend == INT_MIN && divisor == -1))
    {
        return 1;
    }

    total += dividend / divisor;
    if (printf("quotient=%d, remainder=%d, total=%d\n",
               dividend / divisor, dividend % divisor, total) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- 检查除数时必须覆盖 0 和商不可表示的特殊组合，不能只检查 0。
- 不要把有符号溢出当作可检测的回绕；一旦溢出发生，事后的 `if (result < 0)` 不能恢复定义良好的行为。
- 复合赋值左侧若含复杂表达式，只求值一次很重要，但仍须遵守 E03.03 的副作用排序规则。

### 常见问题

**问：`-7 / 2` 的结果为什么是 `-3` 而不是 `-4`？**

答：C99 及之后的整数除法向零截断，而不是向负无穷取整；余数由 `a == (a / b) * b + a % b` 的关系确定，前提是相关运算有定义。

## E03.02 关系、相等与逻辑运算符

- **标签**：`表达式` `比较` `分支` `浮点数`
- **难度**：入门
- **前置**：E02.02、E02.06
- **关联**：E03.05、E04.01、E04.03

### 概念解释

关系和相等运算符比较操作数，逻辑运算符组合真假条件；它们都产生类型为 `int` 的 0 或 1。`&&` 与 `||` 的短路求值不仅节省计算，还能用左侧条件保护右侧可能无效的操作。

### 语法要点

- 关系运算符为 `<`、`>`、`<=`、`>=`，相等运算符为 `==`、`!=`；不要把赋值 `=` 错写成相等比较。
- 逻辑与 `&&`：左侧为假则不计算右侧；逻辑或 `||`：左侧为真则不计算右侧；`!` 对真假取反。
- `&&`、`||` 的左侧求值及其副作用先于右侧，普通函数参数和多数二元算术运算符没有这种保证。
- 混合类型的比较会先执行通常算术转换，有符号负值与无符号值比较时尤其需要检查。
- 链式写法 `0 < x < 10` 等价于 `(0 < x) < 10`，第一次比较只得 0 或 1，不能表达数学区间。

### 使用场景

短路适合验证前置条件，例如先确认除数非零再做除法。浮点计算后的相等判断应结合 E02.02 的误差模型；多个条件应拆开写清楚，不要依赖链式比较的数学外观。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int value = 20;
    int divisor = 0;

    if (divisor != 0 && value / divisor > 2)
    {
        puts("quotient is large");
    }
    else
    {
        puts("division is not evaluated");
    }

    if (ferror(stdout))
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- 区间条件写成 `x > 0 && x < 10`，并确保 `x` 已初始化且类型转换符合预期。
- 短路只对 `&&`、`||` 和条件运算符等明确规定；把保护条件放入普通函数实参并不能保护另一个实参。
- 示例中的 `ferror(stdout)` 检查输出流错误；对关键输出也可直接检查 `printf` 或 `puts` 的返回值。

### 常见问题

**问：`a != b` 与 `!(a == b)` 总等价吗？**

答：对普通有定义的比较通常等价，包括 NaN 的相等规则：NaN 与任何值不相等。但操作数的类型转换、副作用及其他运算仍须分别分析，不能借此推广到所有表达式重写。

## E03.03 自增、自减与副作用排序

- **标签**：`表达式` `赋值` `未定义行为` `循环`
- **难度**：进阶
- **前置**：E03.01
- **关联**：E03.02、E04.03、E05.02

### 概念解释

`++` 和 `--` 既计算表达式的值，又修改操作数对象，因此带有副作用。C11/C17 用“先排序于”（sequenced before）描述求值与副作用的先后；若同一标量对象的多个修改没有足够排序，程序可能产生未定义行为。

### 语法要点

- 前缀 `++i` 的结果是增加后的值；后缀 `i++` 的结果是增加前的值，但副作用不要求在表达式值产生时立刻完成。
- 操作数必须是可修改的标量左值；数组名、字面量和 `const` 对象不能直接自增。
- 一个完整表达式结束时有相应排序保证，因此 `i++;` 与 `++i;` 各自单独作为语句时效果相同。
- `i = i++ + 1;`、`i++ + i++`、`f(i++, i++)` 等写法存在未排序的读取/修改或多次修改，属于未定义行为。
- 函数实参的求值顺序未指定；即使实参之间没有未定义行为，也不能假定从左到右执行。

### 使用场景

自增自减适合独立语句和 `for` 的迭代表达式。涉及同一变量多个副作用时，应拆成多条语句并保存中间结果；不要把“更短”置于“求值顺序明确”之上。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int value = 5;
    int old_value = value++;
    int new_value = ++value;

    /* 错误示例（不执行）：value = value++ + 1; */

    if (printf("old=%d, new=%d, value=%d\n",
               old_value, new_value, value) < 0)
    {
        return 1;
    }

    return 0;
}
```

完整程序输出 `old=5, new=7, value=7`，每条副作用都由完整表达式边界分开。

### 注意事项

- 编译器未报警不代表表达式有定义；这类错误可能在不同优化级别下表现不同。
- 不要把后缀形式理解为“整条语句结束后才加一”，它的精确语义是值计算与副作用按标准排序，而非固定延迟到分号。
- 更新计数器还要考虑有符号溢出；自增达到可表示范围之外同样是未定义行为。

### 常见问题

**问：为什么 `printf("%d %d", i++, i++)` 不能只是输出顺序不确定？**

答：两个实参对同一标量对象的修改在 C11/C17 中没有足够排序，因此不是二选一的合法顺序，而是未定义行为；应先用独立语句取得两个值，再调用 `printf`。

## E03.04 位运算、掩码与移位

- **标签**：`位运算` `整数` `实现定义` `未定义行为`
- **难度**：进阶
- **前置**：E02.01、E02.06
- **关联**：E03.01、E03.05

### 概念解释

位运算直接处理整数表示中的位，可用于标志、掩码和紧凑编码。无符号整数具有最清晰的模运算和移位语义；有符号负数的表示与右移细节在 C11/C17 中不能一律按某个 CPU 的行为推断。

### 语法要点

- `&` 按位与、`|` 按位或、`^` 按位异或、`~` 按位取反；`&&`、`||` 是逻辑运算，不可互换。
- `x & mask` 保留掩码选中的位，`x | mask` 置位，`x ^ mask` 翻转位，`x & ~mask` 清除位。
- 移位计数为负，或不小于提升后左操作数类型的宽度，行为未定义。
- 无符号左移按模规则计算；有符号左移要求原值非负且结果可表示，否则行为未定义。
- 无符号右移补 0；有符号非负值右移等价于除 2 的幂，负值右移的结果由实现定义。

### 使用场景

适合硬件寄存器、权限标志和二进制协议。需要逻辑判断时使用 `&&`，需要检查单个位时使用 `&` 并显式与 0 比较；涉及负数或接近类型宽度的移位，应先重新确认类型和范围。

### 示例

```c
#include <stdio.h>

int main(void)
{
    const unsigned int read_flag = 1u << 0;
    const unsigned int write_flag = 1u << 1;
    unsigned int flags = read_flag | write_flag;

    flags &= ~read_flag;
    if ((flags & write_flag) != 0u)
    {
        if (printf("flags=%u\n", flags) < 0)
        {
            return 1;
        }
    }

    return 0;
}
```

### 注意事项

- `1 << 31` 若 `int` 为 32 位且最高位是符号位，可能未定义；构造无符号掩码应从 `1u` 或目标无符号类型常量开始。
- 操作数会先经历整数提升，小类型上的 `~` 可能产生意外高位；赋值回小类型前应按需掩码。
- 位运算不能替代边界检查，序列化仍须明确字节序、字段宽度和有效位。

### 常见问题

**问：右移负数是否总相当于除以 2？**

答：不能这样假设。C11/C17 对负有符号值的右移作实现定义规定；若需要可移植的逻辑右移，应先设计合适的无符号表示并明确转换代价。

## E03.05 优先级、结合性与条件运算符

- **标签**：`表达式` `优先级` `分支` `未定义行为`
- **难度**：进阶
- **前置**：E03.01、E03.02
- **关联**：E03.03、E04.01

### 概念解释

优先级决定运算符如何分组，结合性决定同级运算符向哪边分组，二者都不等于完整的运行时求值顺序。条件运算符 `?:` 根据条件只计算两个分支之一，是表达式形式的选择结构。

### 语法要点

- 常见优先级由高到低为后缀运算、单目运算、乘除模、加减、移位、关系、相等、位与、异或、位或、逻辑与、逻辑或、条件、赋值、逗号。
- 同级算术通常左结合，如 `a - b - c` 为 `(a - b) - c`；赋值和条件运算右结合。
- 括号能改变分组，但不能自动规定函数实参或普通二元操作数的求值先后。
- `condition ? value1 : value2` 先计算标量条件；条件为真只算 `value1`，否则只算 `value2`。
- 条件运算符会根据后两个操作数确定结果类型，常见算术操作数会执行通常算术转换；复杂类型组合需查对应规则。

### 使用场景

条件运算符适合从两个简单值中选择一个，如状态文本或较小值。分支中含复杂计算、资源操作或多个语句时，`if` 通常更清楚；优先级不确定时加括号，不要用记忆表格掩盖可读性问题。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int score = 82;
    const char *result = score >= 60 ? "pass" : "retry";
    int grouped = (2 + 3) * 4;

    if (printf("result=%s, grouped=%d\n", result, grouped) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- `a + b << 2` 表示 `(a + b) << 2`，而 `a & mask == 0` 可能并非预期分组；位掩码条件建议写成 `(a & mask) == 0`。
- 条件表达式只计算选中的分支，但不能用它隐藏必要错误处理，例如资源释放通常更适合完整语句。
- 不要写嵌套多层且带副作用的 `?:`；即使优先级正确，也会显著增加审查难度。

### 常见问题

**问：给表达式全部加括号后，函数实参就会从左到右求值吗？**

答：不会。括号只明确分组，不改变实参求值顺序未指定的规则；有顺序要求的副作用必须拆成独立语句。
