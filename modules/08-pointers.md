# M08 指针

> 本模块解释指针如何表示对象地址、如何通过间接访问读写对象，以及这些操作何时有效。学完后应能区分指针与数组，正确表达 `const` 契约，使用多级指针和函数指针设计接口，用 `void *` 传递通用对象地址，并识别空指针、悬空指针和越界指针造成的未定义行为。

## E08.01 取地址、解引用与指针有效性

- **标签**：`指针` `生命周期` `未初始化` `未定义行为`
- **难度**：入门
- **前置**：E05.01、E06.01
- **关联**：E08.02、E08.07、E11.01

### 概念解释

指针是值为另一对象地址的对象。一元 `&` 取得可寻址对象的地址，一元 `*` 对指针解引用以访问其指向的对象；指针变量自身也有类型、存储期和值，不能把“指针有效”和“指针非空”混为一谈。

一个可用于读写的指针必须指向仍处于生命周期内、类型兼容且具有所需访问权限的对象。非空但已失效的地址、未初始化的指针以及越界形成的地址都不能安全解引用。

### 语法要点

- `int value = 42; int *p = &value;` 中，`p` 的类型是“指向 `int` 的指针”，`*p` 是 `value` 的左值表达式。
- `*p = 50;` 修改被指向对象；`p = NULL;` 只修改指针本身，不修改原来的 `value`。
- 空指针常量 `NULL` 可用于初始化、比较和表示“没有对象”；对空指针解引用是未定义行为。
- 取地址要求对象可寻址；不能对位域使用 `&`，也不能把临时构造的非法地址当作长期指针保存。
- `*p` 的对象访问受有效类型、对齐和边界约束；仅通过强制转换改变指针类型不会使原对象变成另一种类型。

### 使用场景

适合让函数修改调用者对象、遍历数组、引用较大结构体而避免复制，以及表达可选输出。若只是读取小型值，直接传值往往更简单；不要为了“使用指针”而引入不必要的别名和生命周期依赖。

### 示例

```c
#include <stdio.h>

static void increment(int *value)
{
    if (value != NULL)
    {
        ++*value;
    }
}

int main(void)
{
    int count = 10;
    int *pointer = &count;

    printf("修改前：%d\n", *pointer);
    increment(pointer);
    printf("修改后：%d\n", count);

    pointer = NULL;
    increment(pointer);
    return 0;
}
```

### 注意事项

- **错误：`int *p; *p = 1;`**。`p` 未初始化，不能通过“给它赋一个整数地址”修复；应让它指向有效对象或动态分配对象。
- `if (p != NULL)` 只能排除空指针，不能检测悬空、越界或未初始化指针。
- 将指向对象的指针用于写操作时，该对象必须可修改；指向 `const` 对象或字符串字面量的指针不能绕过限制写入。
- 结构体或数组传指针时，要在接口文档中说明调用者必须保持其生命周期到何时。

### 常见问题

**问：`&value` 和 `value` 的值有什么不同？**

答：`value` 是对象当前的整数值，`&value` 是该对象的地址。把地址保存在 `int *` 中后，解引用才能按 `int` 的语义访问这个对象；地址不是可以直接当作普通整数随意计算的通用数值。

## E08.02 指针与数组的转换、下标和指针运算

- **标签**：`指针` `数组` `边界检查` `越界` `未定义行为`
- **难度**：进阶
- **前置**：E08.01、E06.02
- **关联**：E07.01、E08.03、E08.07

### 概念解释

数组和指针是不同类型，但数组名在大多数表达式中会转换为指向首元素的指针，这就是“数组到指针衰减”。因此函数参数中的 `int values[]` 实际等价于 `int *values`，函数不会自动知道原数组长度，必须另行传递元素数。

指针运算以所指向类型的元素为单位。对数组内指针加一得到下一元素地址；可形成指向末尾后一个位置的“尾后指针”用于比较，但不能解引用它。

### 语法要点

- 对数组 `int a[4]`，`a[i]` 等价于 `*(a + i)`，`&a[i]` 是指向第 `i` 个元素的指针。
- `a` 衰减后是 `int *`，而 `&a` 是 `int (*)[4]`；二者地址数值可能相同，但类型和加一的步长不同。
- `sizeof a` 在数组仍是数组的作用域内得到整个数组字节数；函数形参已是指针，`sizeof` 不再提供元素数。
- 指针加减整数必须保持在同一数组对象及其尾后位置内；两个指针相减也要求指向同一数组对象（含尾后），结果是 `ptrdiff_t` 元素数而非字节数。
- 访问 `a[count]` 在 `count` 等于元素数时已经越界；尾后指针只能作为边界标记。

### 使用场景

适合写接收数组切片的函数、实现迭代器和计算连续数据范围。非连续容器、不同对象的指针关系或任意整数地址运算不能套用数组指针规则。

### 示例

```c
#include <stddef.h>
#include <stdio.h>

static int sum(const int *values, size_t count)
{
    int total = 0;
    for (size_t i = 0; i < count; ++i)
    {
        total += values[i];
    }
    return total;
}

int main(void)
{
    int values[] = { 2, 4, 6, 8 };
    size_t count = sizeof values / sizeof values[0];
    const int *end = values + count;

    printf("总和：%d\n", sum(values, count));
    printf("末元素：%d\n", *(end - 1));
    printf("元素数：%td\n", end - values);
    return 0;
}
```

### 注意事项

- 示例 `sum` 对 `total` 的整数溢出没有额外处理；真实接口应规定值域或采用更宽类型并检查结果，不能把数组边界安全误认为所有运算都安全。
- `values + count` 是合法尾后指针，`*(values + count)` 是未定义行为；循环条件应使用索引或边界，不要读取尾后元素。
- **危险：把 `sizeof` 形参数组当作长度。** 应在调用处用 `sizeof values / sizeof values[0]` 计算并显式传入。
- 指针加减的单位是 `sizeof *pointer`，不要把字节偏移直接加到非 `char` 指针上；原始字节访问可使用 `unsigned char *`。

### 常见问题

**问：既然 `a` 能传给 `int *` 参数，是否可以说数组就是指针？**

答：不可以。数组拥有连续元素存储，`sizeof a` 和 `&a` 体现其数组类型；指针只保存地址，且可以被重新赋值。衰减是表达式中的类型转换规则，不是数组对象变成了指针对象。

## E08.03 const 指针与只读接口契约

- **标签**：`指针` `类型系统` `声明与定义` `可移植性`
- **难度**：进阶
- **前置**：E08.01、E08.02
- **关联**：E05.03、E09.02、E11.03

### 概念解释

`const` 与指针组合时，需要分别回答“能否修改指向的对象”和“能否修改指针本身”。`const int *` 是通过该指针只读地访问 `int`，`int *const` 是指针值固定但对象可写，`const int *const` 两者都固定。

参数中的 `const` 是接口契约：它告诉调用者函数不会经此参数修改对象，也让指向 `const` 对象的指针能够安全传入。它不会复制对象，也不会保证对象不会被别的别名或外部因素修改。

### 语法要点

- `const int *p` 与 `int const *p` 等价：`p` 可改指，`*p` 不可经此表达式赋值。
- `int *const p = &value;`：`p` 不可改指，`*p` 可写；必须初始化，因为之后不能给指针本身赋值。
- `const int *const p = &value;`：指针和经它访问的对象均不可修改。
- 函数参数写 `const int *values` 只限制函数经该指针的访问；调用者仍可在不重叠的合适时机修改自己的数组。
- 不能用强制类型转换去掉 `const` 后修改原本定义为 `const` 的对象，行为未定义；转换也不会使字符串字面量可写。

### 使用场景

适合只读查找、打印、比较和算法输入参数，以及需要固定游标但允许写元素的局部场景。输出参数、需要原位排序的数组则不能使用指向 `const` 的指针。

### 示例

```c
#include <stddef.h>
#include <stdio.h>

static void print_values(const int *values, size_t count)
{
    for (size_t i = 0; i < count; ++i)
    {
        printf("%d%c", values[i], i + 1 == count ? '\n' : ' ');
    }
}

int main(void)
{
    int values[] = { 1, 2, 3 };
    const int *read_only = values;
    int *const fixed_pointer = values;
    const int *const locked_pointer = values;

    *fixed_pointer = 10;
    read_only = values + 1;
    printf("read_only 指向：%d\n", *read_only);
    printf("locked_pointer 指向：%d\n", *locked_pointer);
    print_values(values, sizeof values / sizeof values[0]);
    return 0;
}
```

### 注意事项

- `const int *` 不表示对象从此全局只读，只表示不能经这个指针修改；其他可写别名仍可能改变对象。
- 不要把 `const` 当作线程同步或快照机制；共享对象的并发修改仍需同步规则。
- **错误：对字符串字面量使用 `(char *)literal` 后写入。** 强制转换不会获得写权限，仍可能产生未定义行为。
- 阅读复杂声明时可从标识符向外读，或借助 `typedef` 降低声明复杂度，避免把 `const` 放错层级。

### 常见问题

**问：为什么只读函数通常写 `const int *`，而不是 `int *const`？**

答：前者保护被读取的元素，符合只读接口的目的；后者只固定函数内部的指针副本，调用者根本看不到这个指针被改指，通常没有接口价值。若两者都需要固定，才使用 `const int *const`。

## E08.04 多级指针与输出参数

- **标签**：`指针` `参数传递` `返回值` `生命周期` `未定义行为`
- **难度**：进阶
- **前置**：E08.01、E08.03
- **关联**：E07.06、E09.02、E11.04

### 概念解释

多级指针保存另一指针对象的地址。常见用途不是“指向更多维数据”，而是让函数修改调用者的指针，例如输出一个元素位置、更新链表头或替换动态缓冲区。`int **` 要求最终指向一个 `int *` 对象，不能通过随意强制转换把无关对象伪装成它。

输出参数必须有清晰的成功条件、空指针契约和结果生命周期。函数写入调用者的指针对象，并不会自动延长被指向数据的生命周期。

### 语法要点

- `int value; int *p = &value; int **pp = &p;` 中，`*pp` 是 `p`，`**pp` 是 `value`。
- `bool find_first(int *values, size_t count, int **out)` 可通过 `*out = &values[i]` 返回内部元素地址。
- 函数开始时可验证 `out != NULL`，并只在成功时写入 `*out`；失败时让调用者保留原值或明确设为 `NULL`。
- 返回的 `int *` 指向 `values` 内部时，调用者必须保证数组仍存在且没有被导致失效的操作替换。
- `int **` 与二维数组 `int a[3][4]` 不是同一类型；二维数组衰减后是 `int (*)[4]`，不能直接当作 `int **` 使用。

### 使用场景

适合查找函数返回可写元素位置、动态分配函数输出新缓冲区，以及链表插入时统一处理头节点和普通节点。若只输出一个小整数，普通 `int *` 输出参数或直接返回结构体通常更简单。

### 示例

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

static bool find_positive(int *values, size_t count, int **out)
{
    if (out == NULL || (values == NULL && count != 0))
    {
        return false;
    }

    for (size_t i = 0; i < count; ++i)
    {
        if (values[i] > 0)
        {
            *out = &values[i];
            return true;
        }
    }
    return false;
}

int main(void)
{
    int values[] = { -3, 0, 7, 9 };
    int *selected = NULL;

    if (find_positive(values, sizeof values / sizeof values[0], &selected))
    {
        *selected = 70;
        printf("选中并修改为：%d\n", values[2]);
    }
    else
    {
        puts("没有正数或参数无效");
    }
    return 0;
}
```

### 注意事项

- 写入 `*out` 前必须检查 `out`，写入 `**out` 前还必须确认 `*out` 指向有效对象；两层指针不能一次判空代替两层检查。
- 示例返回的 `selected` 是 `values` 的别名，不拥有数组，也不能在数组离开作用域后使用。
- **错误：返回局部变量的地址。** 例如函数内 `int local; *out = &local;` 后返回，调用者得到的指针在函数返回后悬空。
- 若输出参数在失败时应清空，必须把它写进接口契约；否则调用者不应假设失败会改变原值。

### 常见问题

**问：`int **` 是否就是二维数组的通用参数类型？**

答：不是。`int **` 指向一个指针对象，而二维数组的每行连续存储，衰减后类型是“指向含若干个 `int` 的数组的指针”。要接收二维数组，应声明对应列数的数组指针参数，或使用明确的扁平化索引。

## E08.05 函数指针与回调

- **标签**：`指针` `函数指针` `参数传递` `类型系统` `未定义行为`
- **难度**：进阶
- **前置**：E08.01、E05.04
- **关联**：E10.04、E15.01、E17.01

### 概念解释

函数指针保存与特定函数类型兼容的函数地址，使调用者可以把操作作为参数传入，形成回调或策略选择。函数类型包括返回类型和参数类型；签名不兼容时，即使强制转换后“看起来能调用”，也可能产生未定义行为。

函数指针与对象指针属于不同类别。ISO C 不保证函数指针能转换成 `void *` 后再还原，因此通用回调数据可用 `void *`，回调函数本身应使用明确的函数指针类型。

### 语法要点

- `typedef int (*binary_operation)(int, int);` 定义“指向接收两个 `int` 并返回 `int` 的函数”的类型别名。
- 函数名在多数表达式中转换为函数指针，`operation = add` 与 `operation = &add` 可表示同一地址。
- 调用可写 `operation(a, b)` 或 `(*operation)(a, b)`；前者通常更直观。
- 可选回调必须检查是否为 `NULL`；对空函数指针调用是未定义行为。
- 带用户上下文的回调常用 `int apply(int a, int b, binary_operation op)`，需要额外状态时再传 `void *context`，并约定其类型和生命周期。

### 使用场景

适合排序比较器、事件处理、策略模式和表驱动状态机。简单的一次性分支不一定需要函数指针；如果回调需要捕获局部状态，ISO C 没有闭包，应显式传递上下文。

### 示例

```c
#include <stdio.h>

typedef int (*binary_operation)(int, int);

static int add(int left, int right)
{
    return left + right;
}

static int subtract(int left, int right)
{
    return left - right;
}

static int apply(int left, int right, binary_operation operation)
{
    if (operation == NULL)
    {
        return 0;
    }
    return operation(left, right);
}

int main(void)
{
    binary_operation operation = add;
    printf("加法：%d\n", apply(8, 3, operation));

    operation = subtract;
    printf("减法：%d\n", apply(8, 3, operation));
    return 0;
}
```

### 注意事项

- 示例用返回值 `0` 表示空回调仅是教学简化；真实接口若 `0` 也是合法结果，应另设错误通道，不要混淆结果和失败。
- 不要通过参数不同的函数指针调用函数；强制转换只能隐藏编译器诊断，不能修复调用约定和类型不匹配。
- 回调中若保存上下文指针，必须确保回调执行时上下文仍有效；异步注册还要明确注销和销毁顺序。
- 函数指针的比较和转换规则与对象指针不同，不能依赖平台上函数地址恰好等同于数据地址。

### 常见问题

**问：能否把所有回调都声明成 `void *`，调用时再转换为不同函数类型？**

答：不应这样做。`void *` 是通用对象地址类型，不是通用函数地址类型；不同签名也没有统一的调用方式。为每种回调定义准确的函数指针类型，并只传递兼容函数，才能获得类型检查。

## E08.06 void 泛型指针与对象表示访问

- **标签**：`指针` `类型系统` `类型转换` `可移植性` `别名`
- **难度**：进阶
- **前置**：E08.01、E08.02
- **关联**：E09.03、E11.02、E12.03

### 概念解释

`void *` 是可以保存对象地址的通用指针类型，常用于“调用者知道具体类型、通用函数只搬运或转发地址”的接口。C 允许对象指针与 `void *` 相互转换而无需显式强制转换，转回原类型可恢复原地址；但 `void *` 本身没有目标类型，不能直接解引用或做指针算术。

通用指针不携带长度、所有权、对齐或有效类型信息。接口必须由其他参数和契约补齐这些信息，否则通用性只会把类型错误推迟到运行时。

### 语法要点

- `void *data = &value; int *ip = data;` 在 C 中合法；转换回指向原对象类型的指针后可正常访问。
- 访问任意对象的表示字节可使用 `const unsigned char *`；这种访问不要求把对象重新解释成任意其他类型。
- `memcpy(dest, src, n)` 接收 `void *`，但调用者必须保证目标容量、源可读长度、对象有效以及区间不重叠。
- 通过不兼容类型的左值访问有类型对象可能违反有效类型或别名规则；强制转换不会绕过对齐要求。
- `void *` 不表示“拥有内存”，也不保证能保存函数指针；释放规则由分配和所有权契约决定。

### 使用场景

适合实现 `memcpy` 一类字节操作、回调上下文、通用容器接口和二进制 I/O。若函数实际只处理一种类型，应保留具体指针类型以获得编译期检查。

### 示例

```c
#include <stdio.h>

static void print_bytes(const void *object, size_t size)
{
    const unsigned char *bytes = object;
    for (size_t i = 0; i < size; ++i)
    {
        printf("%02x%c", bytes[i], i + 1 == size ? '\n' : ' ');
    }
}

int main(void)
{
    unsigned int value = 0x1234abcdU;
    const void *address = &value;

    printf("value 的对象表示（字节顺序由实现决定）：\n");
    print_bytes(address, sizeof value);
    return 0;
}
```

### 注意事项

- 输出的是本机对象表示，不应据此推断跨平台字节序、整数宽度或文件格式；持久化格式需显式规定编码。
- 在 C 中不必给 `malloc` 的 `void *` 返回值强制转换；转换反而可能掩盖缺少原型等错误，详见 E11.02。
- **危险：把 `void *` 转成未对齐的错误类型后解引用。** 地址有效不代表对齐和有效类型正确，仍可能未定义。
- 通用接口必须同时传递对象大小或元素数，并说明调用期间对象不能被销毁或并发改写。

### 常见问题

**问：`void *` 能否指向任何数据并安全地随时读取？**

答：它能保存对象地址，但读取仍受原对象类型、对齐、生命周期和长度约束。只有把地址恢复为兼容类型，或按 `unsigned char` 检查对象表示，才有明确的访问规则。

## E08.07 空指针、悬空指针、越界与别名风险

- **标签**：`指针` `悬空指针` `越界` `未初始化` `别名` `未定义行为`
- **难度**：工程
- **前置**：E08.01、E08.02、E08.06
- **关联**：E11.01、E11.07、E18.01

### 概念解释

无效指针是值不能用于预期访问的指针，包括空指针、未初始化指针、对象生命周期结束后的悬空指针，以及越过数组边界形成的非法结果。尾后指针是特殊的合法边界值，但仍不可解引用；非空和地址数值看起来合理都不能证明有效性。

指针问题常表现为“有时能运行”，因为未定义行为不要求立即崩溃。工程上应通过接口边界、索引检查、所有权规则和生命周期设计消除无效访问，而不是依赖观察到的偶然结果。

### 语法要点

- 空指针可与 `NULL` 比较，但不能 `*p`、`p[i]` 或对其做以对象为前提的运算。
- 函数返回局部变量地址、释放后继续访问、数组越界和对象类型不匹配都可能导致未定义行为。
- 只有在同一数组对象（含尾后位置）内，指针关系比较和相减才有标准语义；不要随意比较两个独立对象的地址大小。
- 访问数组第 `index` 项前先检查 `index < count`；`count == 0` 时没有任何可解引用元素。
- 通过指针写对象时还要考虑别名：同一对象的多个可写指针可能使修改顺序和编译器假设变复杂，`restrict` 更有严格的不重叠前提。

### 使用场景

适合设计带索引的安全访问器、可空查找结果和调试检查。不要用“指针非空”作为完整输入验证，也不要在未确定生命周期时把内部指针缓存到全局或长期结构中。

### 示例

```c
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>

static bool read_at(const int *values, size_t count,
                    size_t index, int *output)
{
    if (output == NULL || (values == NULL && count != 0))
    {
        return false;
    }
    if (index >= count)
    {
        return false;
    }

    *output = values[index];
    return true;
}

int main(void)
{
    int values[] = { 10, 20, 30 };
    int result;

    if (read_at(values, 3, 1, &result))
    {
        printf("索引 1：%d\n", result);
    }
    if (!read_at(values, 3, 3, &result))
    {
        puts("索引 3 超出边界，未读取");
    }
    return 0;
}
```

### 注意事项

- **错误：先访问再检查。** `*output = values[index]; if (index < count) ...` 已经发生越界，后续检查无法撤销未定义行为。
- 指针被 `free` 后即使其数值未变也不能解引用；释放所有权后将指针置空可防止部分误用，但不能清除其他别名，详见 E11.07。
- 不要把一个对象的指针强转为不兼容结构体指针后读取字段；对齐和有效类型要求仍然存在。
- 运行时检查工具和编译器警告有助于发现问题，但不能证明所有路径都安全；应优先写清晰的边界和生命周期契约。

### 常见问题

**问：为什么访问已经 `free` 的内存有时还能读到旧值？**

答：未定义行为允许任何结果，旧值暂时残留只是某种实现的偶然表现。释放后对象生命周期已结束，读取、写入甚至依赖其内容进行指针运算都不可作为正确程序的依据。
