# M06 数组

> 本模块介绍数组的连续存储、初始化和边界规则，说明数组参数为何退变为指针，并扩展到多维数组与变长数组。学完后应能安全传递数组及长度、遍历每一维，并避免越界、错误长度计算和不受控的 VLA。

## E06.01 一维数组、元素布局与初始化

- **标签**：`数组` `初始化` `生命周期` `未初始化`
- **难度**：入门
- **前置**：E02.04、E02.05
- **关联**：E06.02、E06.05

### 概念解释

数组是连续分配的、同类型元素组成的对象；长度为 `n` 时，有效下标从 0 到 `n - 1`。数组对象不是可整体赋值的普通变量，它的长度和初始化方式在定义时确定，VLA 则有额外的运行时规则。

### 语法要点

- `int values[4];` 定义 4 个连续 `int` 元素；普通定长数组的长度是大于 0 的整数常量表达式。
- `int values[4] = {10, 20};` 显式初始化前两个元素，其余元素零初始化，因此后两个为 0。
- `int values[] = {10, 20, 30};` 由初始化器推得长度 3；`int values[4] = {0};` 可把所有元素初始化为 0。
- 未显式初始化的自动数组元素值不确定，静态数组则零初始化；读取不确定元素可能产生未定义行为。
- 数组名不能作为赋值左侧，`array1 = array2` 不合法；复制应逐元素进行或使用符合容量要求的库操作。

### 使用场景

适合元素数量已知、类型相同且需要连续存储的数据，如固定采样窗口或查找表。运行期间频繁改变数量时，应考虑动态存储和容量管理，而不是定义一个“足够大的”数组后忽略实际长度。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int readings[5] = {10, 20};

    if (printf("first=%d, third=%d, last=%d\n",
               readings[0], readings[2], readings[4]) < 0)
    {
        return 1;
    }

    return 0;
}
```

输出中前两个元素分别为 10、20，第三到最后一个元素均因部分初始化而为 0。

### 注意事项

- 初始化器数量不能超过数组长度；编译器应诊断这一约束违反，不要依赖截断。
- `int values[5] = {0};` 与 `int values[5] = {};` 不同，后者在 C11/C17 中不是可移植的空初始化器语法。
- 连续存储不意味着编译器会替你做下标检查；有效范围必须由程序保证。

### 常见问题

**问：`int values[5] = {1};` 是否把 5 个元素都设为 1？**

答：不是。只有第一个元素为 1，其余元素为 0；若要把所有元素设为同一非零值，可逐元素赋值或使用适当的初始化循环。

## E06.02 数组遍历、长度计算与边界检查

- **标签**：`数组` `边界检查` `越界` `未定义行为`
- **难度**：入门
- **前置**：E04.03、E06.01
- **关联**：E06.03、E03.03

### 概念解释

数组遍历必须让索引、指针或迭代次数与实际元素数量一致。C 不在每次访问时自动检查边界，越界读取或写入是未定义行为，可能破坏相邻对象，也可能表面上暂时正常。

### 语法要点

- 对当前作用域中的完整数组，`sizeof array / sizeof array[0]` 可得到元素数，结果为 `size_t`。
- 常用遍历为 `for (size_t i = 0; i < count; ++i)`，有效最后下标为 `count - 1`；空数组不存在于标准普通数组定义中，但元素数变量可为 0 的动态数据视图需另行处理。
- 指向数组尾后一个位置的指针可用于边界比较，但不能解引用；更不能构造或访问远超数组范围的地址。
- 长度计算式用于指针时只会得到指针大小除以元素大小，不能恢复调用前的数组长度。
- 接收外部索引或长度时，必须在访问前验证其范围和换算过程，防止加法、乘法溢出绕过检查。

### 使用场景

适合求和、查找、转换和批量验证。循环条件应直接表达逻辑边界；如果函数收到的是数组参数而不是完整数组对象，长度必须由调用方单独传入，见 E06.03。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int readings[] = {10, 20, 30, 40};
    size_t count = sizeof readings / sizeof readings[0];
    int total = 0;

    for (size_t i = 0; i < count; ++i)
    {
        total += readings[i];
    }

    if (printf("count=%zu, total=%d\n", count, total) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- 使用 `< count` 而不是 `<= count`，后者会访问尾后位置。
- 用 `size_t` 遍历可避免负数索引，但倒序循环要防止 `size_t` 在 0 处下溢。
- 不要依赖越界后程序崩溃来发现问题；未定义行为也可能悄悄修改数据并继续运行。

### 常见问题

**问：为什么有时越界读取仍能打印出看似合理的数？**

答：未定义行为不要求立即崩溃或产生固定错误，某次读到的字节只是偶然现象；应修复索引和长度关系，而不是根据该输出推断数组内容。

## E06.03 数组参数退变与显式长度传递

- **标签**：`数组` `指针` `参数传递` `边界检查`
- **难度**：进阶
- **前置**：E05.02、E06.02
- **关联**：E06.04、E05.05

### 概念解释

数组用于大多数表达式时会转换为指向首元素的指针，函数形参中的数组写法也会调整为指针。因此函数并未接收整个数组副本，也无法仅凭该指针知道元素数量；长度是接口必须另行表达的信息。

### 语法要点

- `void f(int values[10]);`、`void f(int values[]);` 与 `void f(int *values);` 的形参类型调整后相同，方括号中的 10 不提供边界检查。
- 在函数内 `sizeof values` 得到指针大小，而不是调用方数组总字节数。
- `const int values[]` 表示函数不能通过该参数修改元素，适合只读遍历；它仍需要有效指针和正确长度。
- 典型接口是 `double mean(const int values[], size_t count);`，调用方传入数组首地址和元素数。
- 数组退变的主要例外包括 `sizeof`、一元 `&` 和字符串字面量初始化数组等规定情形；不能把“数组永远是指针”当作严格定义。

### 使用场景

适合编写可处理不同长度数组的通用函数。调用方必须保证指针在调用期间有效且至少有 `count` 个元素；若空指针或零长度有特殊含义，应在接口契约中明确，而不是让调用方猜测。

### 示例

```c
#include <stddef.h>
#include <stdio.h>

double mean(const int values[], size_t count)
{
    double total = 0.0;

    if (values == NULL || count == 0u)
    {
        return 0.0;
    }

    for (size_t i = 0; i < count; ++i)
    {
        total += values[i];
    }

    return total / (double)count;
}

int main(void)
{
    int readings[] = {10, 20, 30, 40};
    size_t count = sizeof readings / sizeof readings[0];
    double result = mean(readings, count);

    if (printf("mean=%.2f\n", result) < 0)
    {
        return 1;
    }

    return 0;
}
```

本例用 0.0 处理空输入只是为了保持示例简短；若空输入是错误，实际接口应像 E05.05 一样单独返回状态。

### 注意事项

- 不要根据函数形参写成 `int values[100]` 就传入较小数组，声明中的数字不会自动保护调用。
- `const` 只限制通过该形参访问元素，不能替调用方保证指针有效或长度正确。
- 若 `count` 与实际容量不一致，即使指针非空也可能越界；错误检查不能恢复缺失的真实容量信息。

### 常见问题

**问：能否在函数内部用 `sizeof values / sizeof values[0]` 求参数数组长度？**

答：不能，因为 `values` 已调整为指针。应在调用方仍能看到完整数组时计算长度，再作为独立参数传入。

## E06.04 多维数组与按行遍历

- **标签**：`多维数组` `数组` `边界检查` `性能`
- **难度**：进阶
- **前置**：E06.01、E06.02
- **关联**：E06.03、E06.05

### 概念解释

多维数组本质上是“数组的数组”。`int matrix[2][3]` 包含 2 个元素，每个元素又是含 3 个 `int` 的数组；元素连续排列，最右下标变化最快，这种布局通常称为行优先。

### 语法要点

- `matrix[row][column]` 先选择行，再选择该行中的列；各维有效下标都从 0 开始。
- 初始化可写成 `{{1, 2, 3}, {4, 5, 6}}`，省略的内层元素按聚合初始化规则零初始化。
- 完整对象上可用 `sizeof matrix / sizeof matrix[0]` 求行数，用 `sizeof matrix[0] / sizeof matrix[0][0]` 求列数。
- 函数参数 `int matrix[][3]` 调整为“指向含 3 个 `int` 的数组”的指针，列数是指针类型的一部分，行数仍需另传。
- 只有最左维的数组形参长度可省略；其他维度决定元素步长，不能随意省略。

### 使用场景

适合矩阵、网格和表格。按内存布局顺序遍历通常有良好局部性；若每行列数在运行时变化，可使用 E06.05 的 VLA 参数或其他明确的动态布局，不能伪造固定列数。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int matrix[2][3] = {
        {1, 2, 3},
        {4, 5, 6}
    };
    size_t rows = sizeof matrix / sizeof matrix[0];
    size_t columns = sizeof matrix[0] / sizeof matrix[0][0];
    int total = 0;

    for (size_t row = 0; row < rows; ++row)
    {
        for (size_t column = 0; column < columns; ++column)
        {
            total += matrix[row][column];
        }
    }

    if (printf("total=%d\n", total) < 0)
    {
        return 1;
    }

    return 0;
}
```

外层遍历行、内层遍历列，与连续布局的顺序一致，结果为 21。

### 注意事项

- 不要把 `int **` 当作 `int matrix[2][3]` 的等价参数；前者指向指针，后者退变后指向数组，布局和类型不同。
- 多维下标也不能越界，即使把二维下标手工折算成一维，仍须验证完整范围和乘法溢出。
- 传递多维数组时保留除最左维外的维度信息，并显式传入实际行数。

### 常见问题

**问：二维数组是否一定由若干行指针组成？**

答：不是。普通 `int matrix[2][3]` 是连续的 6 个 `int`，中间没有行指针对象；指针数组是另一种数据结构。

## E06.05 变长数组 VLA 与初始化限制

- **标签**：`数组` `生命周期` `实现定义` `未定义行为` `C11`
- **难度**：进阶
- **前置**：E05.03、E06.01、E06.03
- **关联**：E06.04、E04.05、E02.05

### 概念解释

变长数组（VLA）的长度由运行时表达式确定，具有自动存储期，大小在进入声明所在块时确定。C99 引入 VLA，C11/C17 允许实现通过 `__STDC_NO_VLA__` 表明不支持，因此可移植工程必须显式考虑这一可选特性。

### 语法要点

- 块内 `int values[count];` 若 `count` 不是整数常量表达式，则声明 VLA；每次执行到声明时求值大小，运行期间长度不再改变。
- VLA 的大小表达式求值后必须大于 0，否则行为未定义；长度换算和对象大小也不能超出实现支持范围。
- VLA 不能有初始化器，`int values[count] = {0};` 是约束违反；必须用循环或其他适当操作初始化。
- VLA 不能有静态或外部链接存储期，也不能用 `goto` 或 `switch` 跳入其作用域。
- 对 VLA 的 `sizeof` 在运行时计算；多维函数参数也可使用运行时维度，但各维度必须在进入函数体前已求值。

### 使用场景

VLA 适合规模较小、有明确上限且只在局部作用域存在的运行时矩阵或工作区。长度来自不可信输入、规模可能很大或要求跨编译器严格可移植时，应考虑带容量检查的动态分配，而不是假设自动存储空间无限。

### 示例

```c
#include <stdio.h>

int main(void)
{
#if defined(__STDC_NO_VLA__) && __STDC_NO_VLA__
    if (puts("VLA is not supported") == EOF)
    {
        return 1;
    }
#else
    size_t count = 4u;
    int values[count];
    int total = 0;

    for (size_t i = 0; i < count; ++i)
    {
        values[i] = (int)(i * i);
        total += values[i];
    }

    if (printf("VLA bytes=%zu, total=%d\n", sizeof values, total) < 0)
    {
        return 1;
    }
#endif

    return 0;
}
```

`values` 的 4 个元素依次初始化为 0、1、4、9；预处理器分支让声明不支持 VLA 的实现避开该定义。

### 注意事项

- 在声明前验证长度下限、合理上限及字节数计算，自动存储耗尽没有可移植的恢复机制。
- VLA 离开声明块后生命周期结束，不能保存其地址供之后使用。
- `__STDC_NO_VLA__` 由实现定义为 1 表示不支持；编译器扩展是否存在不能替代标准特性检测和项目约束。

### 常见问题

**问：VLA 是否就是在堆上自动 `malloc` 的数组？**

答：不是。VLA 具有自动存储期，其实现方式由编译器决定，不等于动态分配；它没有初始化器，也不要求也不能由程序用 `free` 释放。
