# M02 数据类型

> 本模块解释 C 如何表示整数、浮点数、字符和布尔值，以及对象初始化、大小查询、范围检查和类型转换的规则。学完后应能选择合适类型、编写可移植的格式化代码，并识别溢出、精度损失和未定义行为。

## E02.01 整数类型、范围与溢出

- **标签**：`整数` `类型系统` `溢出` `整数溢出` `可移植性`
- **难度**：入门
- **前置**：E01.03
- **关联**：E02.05、E02.06、E03.01、`<limits.h>`

### 概念解释

整数类型保存没有小数部分的数值，包括标准有符号类型 `signed char`、`short`、`int`、`long`、`long long` 及对应无符号类型。标准规定最小范围和相对大小关系，不保证它们在所有平台上都有相同位数；无符号运算按模规则进行，有符号溢出则不是“自动回绕”。

### 语法要点

- 无符号类型取值从 0 到 `2^N - 1`，运算结果按 `2^N` 取模，其中 `N` 是该类型值表示的位数。
- 有符号运算若结果不能由返回类型表示，例如 `INT_MAX + 1`，行为未定义；编译器优化可能据此改变程序逻辑。
- 除法和取模除数为 0 时行为未定义；`INT_MIN / -1` 在商无法表示时同样未定义。
- C11/C17 不要求有符号整数必须采用二进制补码，也不规定普通 `int` 必须是 32 位。
- 可用 `<limits.h>` 中的 `INT_MAX`、`UINT_MAX` 等宏查询范围，不要写死平台假设。

### 使用场景

数组长度、计数器和文件大小常使用整数类型。无符号类型适合模运算、位掩码和明确需要回绕的场景；涉及减法、偏移或与有符号接口交互时，不应只因“不会出现负数”就盲目改用无符号类型。

### 示例

```c
#include <limits.h>
#include <stdio.h>

int main(void)
{
    unsigned int value = UINT_MAX;
    unsigned int wrapped = value + 1u;

    if (printf("wrapped=%u\n", wrapped) < 0)
    {
        return 1;
    }

    return 0;
}
```

无符号 `wrapped` 保证为 0；若改为对达到其最大值的有符号对象加 1，则会产生未定义行为。

### 注意事项

- 在加法前可用 `if (a > UINT_MAX - b)` 检查无符号加法是否回绕；有符号加法也应在操作前依据上下界检查。
- 不要用一次运行结果推断溢出规则；有符号溢出即使表面得到负数，仍属于未定义行为。
- 循环条件中的无符号值不会因小于 0 而终止，倒序遍历应特别检查下溢。

### 常见问题

**问：`unsigned int` 回绕是否意味着有符号整数也会按同样方式回绕？**

答：不是。无符号回绕是标准保证的模运算，有符号溢出是未定义行为；必须分别设计检查，不能套用同一经验。

## E02.02 浮点类型、精度与特殊值

- **标签**：`浮点数` `类型系统` `比较` `可移植性`
- **难度**：入门
- **前置**：E01.03
- **关联**：E02.05、E02.06、E03.02、`<float.h>`、`<math.h>`

### 概念解释

`float`、`double` 和 `long double` 用于近似表示实数，通常由符号、有效数字和指数组成。浮点运算会舍入，很多十进制小数不能被精确表示；具体表示和精度由实现定义，常见 IEC 60559 格式不是所有 ISO C 实现的唯一选择。

### 语法要点

- 浮点字面量 `3.14` 的类型是 `double`，`3.14f` 是 `float`，`3.14L` 是 `long double`。
- `<float.h>` 提供 `DBL_DIG`、`DBL_MAX`、`DBL_EPSILON` 等能力参数；`sizeof` 较大并不直接等于十进制有效位数。
- `<math.h>` 的 `isfinite`、`isnan`、`isinf` 可分类特殊值；NaN 与任何值（包括自身）的相等比较都为假。
- 浮点转整数会丢弃小数部分；若整数部分不能由目标类型表示，行为未定义。
- 浮点异常、舍入模式及额外精度的细节受实现和浮点环境控制，不能只用十进制直觉推断。

### 使用场景

浮点类型适合测量值、科学计算和图形数据，不应直接用于要求逐分准确的财务记账。相等比较应依据算法选择绝对或相对容差；涉及 NaN 时还要先处理无序比较，单一容差公式并不能解决所有数值问题。

### 示例

```c
#include <stdio.h>

int main(void)
{
    double calculated = 0.1 + 0.2;
    double expected = 0.3;

    if (printf("calculated=%.17g, expected=%.17g\n",
               calculated, expected) < 0)
    {
        return 1;
    }

    return 0;
}
```

输出的高精度形式用于观察舍入，并不表示每个实现都必须产生完全相同的文本。

### 注意事项

- 不要用 `==` 判断多步浮点计算是否“理论上相等”；也不要不加分析地对所有浮点数使用固定 `1e-9` 容差。
- 累加大量不同数量级的数可能放大误差，必要时采用更合适的算法或求和策略。
- 输出精度大于有效精度只会显示更多舍入后的数字，不会恢复丢失的信息。

### 常见问题

**问：既然浮点数不精确，是否意味着它不能用于相等比较？**

答：可以比较，但必须理解数据来源和误差模型。经过精确表示的整数或按设计设定的状态值可能适合直接比较；多步近似计算通常需要容差及特殊值处理。

## E02.03 字符类型与布尔值

- **标签**：`字符` `类型系统` `比较` `实现定义`
- **难度**：入门
- **前置**：E01.03
- **关联**：E02.01、E02.04、E03.02、`<stdbool.h>`、`<limits.h>`

### 概念解释

`char` 是存储一个字节和基本执行字符集元素的整数类型；普通 `char`、`signed char`、`unsigned char` 是三种不同类型。布尔值在 C 中表示为标量的真假：0 为假，非 0 为真；`_Bool` 和 `<stdbool.h>` 提供了更清晰的表达方式。

### 语法要点

- 普通 `char` 是否有符号由实现定义；需要保存小整数或处理原始字节时，应明确选择有符号或无符号字符类型。
- `sizeof(char)` 恒为 1，但一个字节包含 `CHAR_BIT` 位，ISO C 不保证它等于 8。
- 字符常量如 `'A'` 在 C 中的类型是 `int`，不是 `char`；其数值取决于执行字符集，不应假定 ASCII。
- 数字字符 `'0'` 到 `'9'` 的编码保证连续，因此 `'7' - '0'` 得到 7；字母的连续性和区位不能普遍假定。
- `<stdbool.h>` 定义 `bool`、`true`、`false` 宏，对应 `_Bool`、1、0；向 `_Bool` 转换时，0 变 0，非 0 变 1。

### 使用场景

`char` 适合字符数据和字符串，布尔类型适合状态与条件结果；需要逐字节查看对象表示时使用无符号字符类型。不要把字符编码值当作人类可读数字直接计算，除非使用了标准保证或有明确字符集约定。

### 示例

```c
#include <stdbool.h>
#include <stdio.h>

int main(void)
{
    char digit = '7';
    bool valid = digit >= '0' && digit <= '9';
    int numeric_value = valid ? digit - '0' : -1;

    if (printf("valid=%d, value=%d\n", (int)valid, numeric_value) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- `'\0'` 是值为 0 的空字符，常用于标记字符串结束；它与字符 `'0'` 不同。
- 字符常量的打印数值不等于字符形状；用 `%c` 输出字符，用合适的整数格式输出编码值。
- 字符能否保存扩展字符集中的单个“人类字符”取决于编码，多字节文本不能简单理解为一个 `char` 就对应一个完整字符。

### 常见问题

**问：`char` 既然能存数字，为什么还要有 `_Bool`？**

答：`_Bool` 规范化任意标量为 0 或 1，明确表达真假意图；`char` 可保存更广泛的整数值和字符数据，两者语义与转换规则不同。

## E02.04 字面常量、const 对象与初始化

- **标签**：`初始化` `类型系统` `声明与定义` `未初始化`
- **难度**：入门
- **前置**：E01.03、E02.01
- **关联**：E02.03、E05.03、E06.01

### 概念解释

字面量直接写出值，如 `42`、`'A'`、`0.5`；`const` 限定对象则表示其值不能通过该左值修改，但它仍是对象，不等同于字面常量。初始化在对象定义时提供初值，与后续赋值发生的时间和语义不同。

### 语法要点

- 整数前缀 `0` 表示八进制、`0x` 表示十六进制；后缀 `u`、`l`、`ll` 可指定无符号或更长类型，字面量最终类型按标准规则确定。
- 浮点字面量默认是 `double`；字符常量类型为 `int`，字符串字面量则是静态字符数组，不能修改其内容。
- `const int limit = 10;` 创建只读的块作用域对象；在 C11/C17 中，这个 `limit` 不是整数常量表达式，不能代替所有要求编译期常量的上下文。
- 自动对象每次进入定义所在块时重新初始化；静态对象在程序启动前初始化，未显式初始化的静态对象零初始化。
- 聚合初始化中未显式给出的元素按静态对象规则零初始化，详见 E06.01；完全未初始化的自动标量对象值不确定。

### 使用场景

字面量适合协议常数和固定初值，`const` 适合表达运行期间不应改变的局部参数或查找表。需要在 `case` 标签、位域宽度或文件作用域数组长度中使用编译期整数常量时，不能把普通块作用域 `const int` 当作等价替代。

### 示例

```c
#include <stdio.h>

int main(void)
{
    const double tax_rate = 0.08;
    unsigned int flags = 0x0fu;
    int decimal = 42;
    double total = decimal * (1.0 + tax_rate);

    if (printf("flags=%u, total=%.2f\n", flags, total) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- 修改由 `const` 限定的对象会产生未定义行为；强制转换去掉 `const` 不会使原对象突然变得可写。
- 不要写以 0 开头的十进制编号，例如 `018` 是无效八进制字面量，`010` 的值是八进制 10，即十进制 8。
- 初始化只解决初值问题，不阻止之后发生数组越界、算术溢出或其他未定义行为。

### 常见问题

**问：`const int n = 5; int a[n];` 在 C 中一定是普通定长数组吗？**

答：不一定。在 C11/C17 中，这个块作用域 `n` 不是整数常量表达式，因此支持 VLA 的实现会把它视为变长数组；普通定长数组应使用真正的常量表达式，见 E06.05。

## E02.05 sizeof、limits 与类型能力查询

- **标签**：`类型系统` `可移植性` `整数` `浮点数`
- **难度**：入门
- **前置**：E02.01、E02.02
- **关联**：E02.06、E06.01、E06.05、`<limits.h>`、`<float.h>`

### 概念解释

`sizeof` 查询类型或表达式结果类型占用的字节数，结果类型为 `size_t`；`<limits.h>` 和 `<float.h>` 则描述整数范围与浮点能力。二者共同用于依据实际实现写代码，而不是把某个桌面平台的布局当成普遍事实。

### 语法要点

- 类型形式写作 `sizeof(int)`，表达式形式可写 `sizeof value`；对表达式求类型大小时，除 VLA 等规定情形外不对表达式求值。
- 结果以 C 的字节为单位，而 `CHAR_BIT` 给出每字节的位数；`sizeof(int) * CHAR_BIT` 才接近存储位数，且还可能含填充位。
- `sizeof` 应用于完整数组时得到整个数组的字节数；数组退变为指针后，查询的只是指针大小，见 E06.03。
- `INT_MIN`、`INT_MAX`、`UINT_MAX`、`LONG_MAX` 等来自 `<limits.h>`；`FLT_DIG`、`DBL_MAX`、`DBL_EPSILON` 等来自 `<float.h>`。
- `sizeof` 的结果使用 `%zu` 输出；`size_t` 是某个无符号整数类型，不应强转为较窄整数来迁就格式。

### 使用场景

适合计算静态数组容量、检查数据结构和生成本地诊断信息。跨文件或网络交换数据时不能直接把本机 `sizeof` 当作协议字段宽度，因为对齐、字节序和表示格式可能不同。

### 示例

```c
#include <float.h>
#include <limits.h>
#include <stdio.h>

int main(void)
{
    int value = 7;
    size_t bytes = sizeof value;

    if (printf("int bytes=%zu, INT_MAX=%d, DBL_DIG=%d\n",
               bytes, INT_MAX, DBL_DIG) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- `sizeof(char)` 必为 1，不代表 `char` 必有 8 位；检查位数要结合 `CHAR_BIT`。
- `sizeof` 不测量字符串当前长度，也不测量动态分配块的实际容量。
- 对 VLA 的 `sizeof` 在运行时求值，相关大小表达式可能产生副作用；不要把普通定长数组的规则机械推广到 VLA。

### 常见问题

**问：`sizeof` 是否总等于对象所有字段或有效数字之和？**

答：不是。对象大小可包含对齐填充，浮点大小也不直接给出十进制精度；应分别使用标准提供的范围和精度宏。

## E02.06 类型转换、通常算术转换与定宽整数

- **标签**：`类型转换` `整数` `可移植性` `实现定义` `未定义行为`
- **难度**：进阶
- **前置**：E02.01、E02.04、E02.05
- **关联**：E03.01、E03.04、`<stdint.h>`、`<inttypes.h>`

### 概念解释

类型转换把值从一种类型变为另一种类型，可隐式发生在赋值、参数传递和混合运算中，也可通过强制转换显式请求。定宽整数来自 `<stdint.h>`，用于需要精确位宽的接口；它解决宽度问题，但不会自动消除有符号溢出、精度损失或符号转换风险。

### 语法要点

- 整数提升会把小整数类型提升为 `int` 或 `unsigned int`；通常算术转换再为二元运算的两侧寻找共同类型，因此表达式类型不一定等于任一操作数表面类型。
- 有符号值转无符号类型时按目标类型模规则转换；无符号值转有符号类型且不能表示时，结果由实现定义，或产生实现定义的信号。
- 浮点转整数会截去小数部分，无法表示时行为未定义；整数转浮点若值在范围内但不能精确表示，会按实现规定的相邻值方向舍入。
- 强制转换语法为 `(目标类型)表达式`，它不改变原对象，也不会修复非法地址访问或超出范围的运算。
- `int32_t`、`uint32_t` 等精确宽度类型是可选的，只在实现提供无填充、恰好相应宽度的类型时定义；`int_least32_t`、`int_fast32_t` 表达最小宽度或速度偏好。
- `<inttypes.h>` 的 `PRId32`、`PRIu32` 等宏与字符串字面量拼接，用于相应定宽类型的可移植格式化。

### 使用场景

二进制协议、文件格式和位掩码常需要定宽类型；普通业务计数优先选择能表达范围且便于接口互操作的类型。混合有符号与无符号运算前应明确共同类型和值域，不要为了消除警告随意添加强制转换。

### 示例

```c
#include <inttypes.h>
#include <stdint.h>
#include <stdio.h>

int main(void)
{
#if defined(UINT32_MAX)
    uint32_t value = UINT32_C(4000000000);
    uint32_t increment = UINT32_C(2);

    if (UINT32_MAX - value < increment)
    {
        fputs("addition would wrap\n", stderr);
        return 1;
    }

    value += increment;
    if (printf("value=%" PRIu32 "\n", value) < 0)
    {
        return 1;
    }
#else
    if (puts("uint32_t is not supported") == EOF)
    {
        return 1;
    }
#endif

    return 0;
}
```

### 注意事项

- `u + (-1)` 中的符号转换可能产生很大的无符号值；先完成通常算术转换，再判断结果，不要只按数学直觉计算。
- `int32_t` 仍是有符号类型，`INT32_MAX + 1` 依旧未定义；`uint32_t` 才按对应模规则回绕。
- 定宽不意味着字节序固定，也不保证不同类型对象可直接按内存字节互换；序列化还需明确编码规则。

### 常见问题

**问：强制转换能否保证转换后的值安全？**

答：不能。强制转换只请求一次类型转换，结果仍受可表示范围、实现定义规则和未定义行为约束；安全来自转换前的范围检查与明确的类型设计。
