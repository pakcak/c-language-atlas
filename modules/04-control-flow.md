# M04 控制结构

> 本模块介绍选择、循环和跳转语句，重点说明条件语义、循环边界、`break`/`continue` 的作用范围及结构化设计。学完后应能把明确的状态转换写成可读控制流，并避免空悬 `else`、意外贯穿和无限循环。

## E04.01 if 与 else 条件分支

- **标签**：`分支` `比较` `作用域`
- **难度**：入门
- **前置**：E03.02、E03.05
- **关联**：E04.02、E05.05

### 概念解释

`if` 根据标量条件的真假选择是否执行一条语句，`else` 提供另一路径。多路互斥判断可写成 `if ... else if ... else`，其本质仍是嵌套的两路分支。

### 语法要点

- 基本形式为 `if (expression) statement` 和 `if (expression) statement else statement`；条件为 0 表示假，非 0 表示真。
- 受控部分若需要多条语句，应使用复合语句 `{ ... }`；只有一条语句时也常建议保留大括号。
- `else` 总是与最近且尚未匹配的 `if` 配对，这就是“空悬 else”规则。
- 在块内声明的对象只在该块作用域中可见，分支结束后不能继续按名称访问。
- C11/C17 的 `if` 条件不能像某些语言那样直接声明变量，应把声明放在条件之前。

### 使用场景

适合互斥条件、范围分类和前置检查。多个条件应明确优先级和重叠关系；若大量分支实际是在区分一个整数的离散取值，`switch` 可能更清晰，但浮点范围判断仍适合 `if`。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int value = -3;

    if (value < 0)
    {
        puts("negative");
    }
    else if (value == 0)
    {
        puts("zero");
    }
    else
    {
        puts("positive");
    }

    if (ferror(stdout))
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- 条件中的 `=` 是赋值，`==` 才是比较；若确实要在条件中赋值，应清楚写出并检查结果是否符合预期。
- 不要只依赖缩进表达嵌套关系，编译器按语法配对 `else`，不会按空格理解意图。
- 提前返回可简化多层参数检查，但返回前必须履行当前函数已有的资源释放责任。

### 常见问题

**问：`else if` 是一个独立关键字组合吗？**

答：不是。它是 `else` 后面紧跟另一条 `if` 语句的常用排版；通过连续嵌套形成按顺序测试的多路分支。

## E04.02 switch、case 与贯穿

- **标签**：`分支` `比较` `整数`
- **难度**：入门
- **前置**：E04.01、E02.01
- **关联**：E04.04、E06.05

### 概念解释

`switch` 根据整数控制表达式的值跳转到匹配的 `case` 标签，未匹配时可进入 `default`。进入某个标签后，后续语句会顺序执行，除非遇到 `break`、返回或其他跳转，这一机制称为贯穿。

### 语法要点

- 形式为 `switch (integer_expression) statement`，控制表达式具有整数类型，并按规则进行整数提升。
- 每个 `case` 后必须是整数常量表达式，转换到控制表达式类型后不得与其他标签重复；`default` 最多一个。
- `break;` 结束当前 `switch`，继续执行其后的语句；缺少它时有意的贯穿应明确注释。
- ISO C 不支持 `case 1 ... 5` 这种区间标签，也不支持直接以字符串作为 `switch` 控制表达式。
- 某一分支需要局部声明时可用 `{ ... }` 建立块，尤其要避免跳入 VLA 作用域等受限制的跳转。

### 使用场景

适合命令代码、枚举状态和离散协议值的分派。若条件涉及范围、浮点或多个无关变量，使用 `if` 更合适；若大量分支具有复杂行为，也可重构为函数而不是无限扩大单个 `switch`。

### 示例

```c
#include <stdio.h>

int main(void)
{
    char command = 'b';

    switch (command)
    {
        case 'a':
        case 'b':
            puts("start");
            break;
        case 'q':
            puts("quit");
            break;
        default:
            puts("unknown command");
            break;
    }

    if (ferror(stdout))
    {
        return 1;
    }

    return 0;
}
```

`'a'` 标签有意贯穿到 `'b'` 的共同处理代码，两个输入因此执行同一动作。

### 注意事项

- 意外遗漏 `break` 会执行后续分支，可能改变状态或重复释放资源；贯穿必须有明确理由。
- `default` 不一定只能放最后，但放最后更符合多数读者习惯；最后一个分支的 `break` 有助于后续增删标签。
- 不要用未初始化对象作为控制表达式，也不要假设字符编码与某个平台的数值一致。

### 常见问题

**问：有 `default` 后是否就可以不检查输入范围？**

答：不可以。`default` 只处理未匹配标签的当前值，业务层仍可能要区分非法输入、未知版本和暂不支持的功能，并给出不同诊断或错误状态。

## E04.03 while 与 for 循环

- **标签**：`循环` `比较` `初始化`
- **难度**：入门
- **前置**：E03.03、E04.01
- **关联**：E04.04、E06.02

### 概念解释

`while` 和 `for` 都在每次循环体执行前测试条件，因此循环体可能一次也不执行。`for` 把初始化、继续条件和迭代动作集中在一处，特别适合有明确计数或索引的遍历。

### 语法要点

- `while (condition) statement` 在每轮前计算条件，为 0 时离开循环。
- `for (init; condition; increment) statement` 先执行一次初始化，再重复“测试条件、执行循环体、执行迭代表达式”。
- `for` 的三个部分都可省略，省略条件等价于恒真；无限循环应有明确退出路径。
- 在 `for` 初始子句声明的变量，其作用域覆盖整个循环并到循环结束为止。
- 循环变量必须在需要时更新；若条件依赖输入或外部状态，还要保证每轮逻辑会重新评估终止条件。

### 使用场景

`for` 适合已知长度和索引范围，`while` 适合“条件成立就继续”的等待或处理过程。遍历数组时使用 `index < length` 而不是 `index <= length`，具体边界见 E06.02。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int sum = 0;
    int remaining = 3;

    for (int i = 1; i <= 5; ++i)
    {
        sum += i;
    }

    while (remaining > 0)
    {
        --remaining;
    }

    if (printf("sum=%d, remaining=%d\n", sum, remaining) < 0)
    {
        return 1;
    }

    return 0;
}
```

### 注意事项

- 不要把循环条件写成永远成立的赋值表达式，也不要漏掉循环变量的更新。
- 若循环条件或迭代动作发生有符号溢出，行为未定义；倒序无符号循环要特别处理 0 的下溢。
- 循环中的副作用应清晰排序，不要在条件里同时多次修改同一对象。

### 常见问题

**问：`for` 是否一定比 `while` 执行得更快？**

答：没有这种保证。二者是控制流表达方式，性能取决于实际生成的代码和具体操作；应按初始化、条件和迭代的组织是否清晰来选择。

## E04.04 do while、break 与 continue

- **标签**：`循环` `分支` `输入验证`
- **难度**：入门
- **前置**：E04.02、E04.03
- **关联**：E04.05、E06.02

### 概念解释

`do while` 先执行循环体再检查条件，因此至少执行一次。`break` 提前结束最近的一层循环或 `switch`，`continue` 跳过本轮剩余语句并开始下一轮，但它们都不是通用的任意跳转工具。

### 语法要点

- 形式为 `do statement while (condition);`，末尾分号属于语法，不能省略。
- `break` 只退出一层最内层循环或 `switch`；嵌套循环需要额外状态、函数返回或谨慎使用 `goto`。
- 在 `while`、`do while` 中，`continue` 转到条件测试；在 `for` 中，先执行迭代表达式，再测试条件。
- `continue` 不会跳过 `for` 的迭代表达式，这使它常与把同样循环改写成 `while` 时的直觉不同。
- `break` 不能用于跳出普通 `if` 块，除非该 `if` 位于可跳出的循环或 `switch` 内，此时结束的仍是外层循环或 `switch`。

### 使用场景

`do while` 适合至少读取或尝试一次的流程，例如先获取输入再验证。`continue` 适合排除不符合条件的项目，`break` 适合找到结果后立即停止；过多跳转使循环契约不清时，应改为函数或重新组织条件。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int attempts = 0;

    do
    {
        ++attempts;
    } while (attempts < 3);

    for (int n = 0; n < 10; ++n)
    {
        if (n % 2 == 0)
        {
            continue;
        }
        if (n > 5)
        {
            break;
        }
        if (printf("%d ", n) < 0)
        {
            return 1;
        }
    }

    if (printf("| attempts=%d\n", attempts) < 0)
    {
        return 1;
    }

    return 0;
}
```

循环输出奇数 `1 3 5`，到 7 时执行 `break`；`do while` 共执行三次。

### 注意事项

- 使用 `continue` 时确认后续迭代仍能推进，尤其是 `while` 中更新语句位于循环体末尾的情况。
- `break` 只退出一层，误以为它能退出所有嵌套循环可能导致重复处理或错误状态。
- `do while` 的首次执行无法由条件阻止，因此循环体中的前置约束必须在进入前保证。

### 常见问题

**问：为什么把含 `continue` 的 `for` 直接改成 `while` 后会死循环？**

答：`for` 的迭代表达式在 `continue` 后仍执行，而手工放进循环体末尾的更新语句可能被 `continue` 跳过；改写时应把更新放到不会被跳过的位置。

## E04.05 goto、return 与结构化流程

- **标签**：`程序结构` `分支` `循环` `错误处理`
- **难度**：进阶
- **前置**：E04.03、E04.04
- **关联**：E05.01、E06.05

### 概念解释

结构化流程优先用顺序、选择和循环表达意图；`goto` 提供同一函数内到命名标签的显式跳转，`return` 则结束当前函数。`goto` 不是天然错误，但无约束地来回跳转会隐藏状态和资源生命周期，应仅用于清楚、局部的控制流模式。

### 语法要点

- 标签形式为 `label_name: statement`，跳转形式为 `goto label_name;`；标签具有函数作用域，不能用它跳到另一函数。
- `return expression;` 把值转换为函数声明的返回类型并返回；`void` 函数使用 `return;`。
- `goto` 可向前或向后跳转，但不能跳入 VLA 的作用域；涉及对象初始化和生命周期时也要遵守相应限制。
- 从 `main` 返回等价于以该值终止程序；从其他函数返回只结束当前调用。
- 跨非局部跳转、信号处理或线程取消还有额外规则，不应把普通 `goto` 当成这些机制的替代品。

### 使用场景

较合理的用途包括跳出多层循环，或让多个失败路径汇入统一的资源清理段。简单单循环退出优先 `break`，分支选择优先 `if`/`switch`；若清理段过长，应进一步拆分函数并明确资源所有权。

### 示例

```c
#include <stdio.h>

int main(void)
{
    int found_i = 0;
    int found_j = 0;
    int found = 0;

    for (int i = 1; i <= 5; ++i)
    {
        for (int j = 1; j <= 5; ++j)
        {
            if (i * j == 12)
            {
                found_i = i;
                found_j = j;
                found = 1;
                goto search_done;
            }
        }
    }

search_done:
    if (found)
    {
        if (printf("%d * %d = 12\n", found_i, found_j) < 0)
        {
            return 1;
        }
    }
    else if (puts("not found") == EOF)
    {
        return 1;
    }

    return 0;
}
```

这里 `goto` 只向前跳到统一的搜索出口，避免了额外的多层标志测试。

### 注意事项

- 不要向后跳转形成隐含循环，也不要让多个入口绕过必要初始化或跳入 VLA 作用域。
- 清理标签应按相反顺序释放已取得的资源，并记录每个资源是否已成功取得，避免重复释放。
- `return` 也会绕过其后的普通清理代码，提前返回前要检查资源所有权。

### 常见问题

**问：是否应完全禁止 `goto`？**

答：不必机械禁止。局部、向前、出口单一的 `goto` 在嵌套退出和集中清理中可能最清楚；随意跳转、交叉进入复杂作用域或替代普通循环的写法则应避免。
