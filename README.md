# C 语言资料库（C Atlas）

一套面向系统学习与快速查阅的中文 C 语言知识库。内容以 ISO C11/C17 为主，必要时标注 C99、C23 或编译器扩展；同时提供 Markdown 源文档与无需联网、无需安装依赖的 HTML 检索页面。

## 快速开始

- **直接查阅**：用浏览器打开 `index.html`，可全文搜索，并按模块、难度和标签筛选。
- **顺序学习**：从下表 M01 开始，按“学习路径”推进；每个条目均含概念、语法、场景、示例、注意事项和常见问题。
- **阅读源文档**：进入 `modules/`，所有知识均以 Markdown 保存，适合编辑器搜索、版本管理和二次整理。
- **更新检索**：修改或新增模块文档后，运行 `python tools/build_index.py`，再刷新页面。

## 推荐学习路径

### 零基础主线

M01 → M02 → M03 → M04 → M05 → M06 → M07 → M08。每学完一个模块，应独立重写示例，并刻意测试空输入、最大值和边界位置。

### 数据结构与实践线

M08 → M09 → M10 → M11 → M17。重点理解“谁拥有这块内存、何时释放、失败如何清理”，再实现链表和动态数组。

### 工程能力线

M12 → M13 → M14 → M15 → M16 → M18。练习将程序拆成多个翻译单元，使用严格警告、调试器和运行时检查工具。

### 快速排错线

先搜索报错或现象（如“段错误”“越界”“重复定义”），再查看 M18 的对照清单，回到相应模块补齐概念。

## 条目与检索约定

- 条目编号为 `E模块号.序号`，例如 `E08.03`；编号稳定，不因调整顺序而复用。
- 每条条目必须包含：**概念解释、语法要点、使用场景、示例、注意事项、常见问题**。
- 标签分为主题、行为、风险、工具、标准五类；标签使用统一名称，详见 `TAGS.md`。
- 难度只有 `入门`、`进阶`、`工程` 三档，表示所需前置知识，不表示主题重要性。
- 搜索支持标题、正文、代码、标签和条目编号；可组合模块与难度筛选。
- 示例默认是可移植 ISO C；涉及 POSIX、Windows 或特定编译器时必须显式标注。

## 维护与验证

在资料库根目录依次运行：

```sh
python tools/build_index.py
python tools/validate_site.py
python tools/validate_examples.py --compile
```

- 第一条会校验 18 个模块的条目编号、必备字段、小节顺序、标签和交叉引用，并重新生成 `INDEX.md`、`data/library.js`、`data/library.json`。
- 第二条检查 HTML 标签、本地资源引用、离线约束、生成数据一致性与 `INDEX.md` 覆盖；若有 Node.js，还会检查前端脚本语法和浏览器数据。
- 第三条把可独立编译的 C 代码提取到 `examples/extracted/`；检测到 C 编译器时执行 `C17` 严格警告下的语法检查。多文件示例、头文件片段、故意错误的示例和 shell/Make/CMake 块不会误判为独立程序。

## GitHub Pages 部署

仓库中的 `.github/workflows/pages.yml` 会在 `main` 分支推送或手动触发时：

1. 检出仓库源文件；
2. 将 Markdown 文档、静态页面、脚本和生成数据复制到 `public/`；
3. 写入 `public/.nojekyll`；
4. 通过 GitHub Actions 配置、上传并部署 Pages。

工作流只依赖本仓库内容，不依赖外部站点或私有令牌。仓库需将 Pages 的 **Source** 设置为 **GitHub Actions**。

## 准确性边界

“能运行”不等于“行为正确”。资料库特别区分：

- **标准保证**：由 ISO C 明确规定的行为。
- **实现定义**：由编译器/平台文档规定，例如 `char` 默认是否有符号。
- **未定义行为（UB）**：标准不施加要求，可能崩溃，也可能表面上正常。
- **未指定行为**：标准给出若干可能结果，但不要求固定选择。

本库用于学习与工程参考，不替代对应平台的 ABI、编译器和标准库文档。
